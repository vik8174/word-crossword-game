# Changelog

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning follows [SemVer](https://semver.org/).

## [Unreleased]

### Added

- A game that cannot be finished can be ended. A room had exactly one way out until now — every word of its crossword answered — so a player whose partner never came back sat in front of a board that would never fill in with nothing to press, every seat being frozen from the deal onwards: a word is dealt to a browser's own identity and the win is read from those same fields, so a player taken out of a game leaves a crossword nobody could ever finish. The room did not even tidy itself away afterwards, since its 24 hours are counted from the last write and a client in a game writes one every fifteen seconds — the player who stayed was themselves the reason the room was still alive. There is now an **End the game** control while a game is on, and both players have it rather than the host alone: after the deal, the words hidden from the host can be answered by the host and by nobody else, so either of them can be the one left stranded. It asks before it acts, because nothing brings the game back, and it asks the same question every time — whether the other player looks present can change while the dialog is open, so a warning that rewrote itself under somebody's finger was not worth having. The room then says what actually happened to it: an ended game carries a terminal status of its own rather than being described as a completed one, which is the difference between a document that records a result and a document that misreports it. Both screens change by themselves within a second, the words that were answered stay in the grid, and nothing nobody answered is spelled out. Marks stop with the game, so an ended room stops pushing its own expiry forward and really does go away within the day instead of living for as long as a tab stays open. Ending a game is not leaving one: a seat still cannot be emptied on its own, and that limit stays, with its reason ([issue #73](https://github.com/vik8174/word-crossword-game/issues/73), [ADR 0027](docs/decisions/0027-a-game-a-player-can-end.md))
- A player's name is remembered between games. Somebody who plays twice used to type the same name twice, there being no accounts to hold it — so the browser holds it: the name a room was created or joined under is kept in that profile's own storage and offered back into both nickname fields, the host's on `/create` and the guest's behind the invite link. Both of them, because the host is the likeliest person in this game to make a second room, and a memory only the guest's form wrote to would have left exactly one player never offered their own name. It is offered rather than imposed — the field is the player's to rewrite, and what they rewrite it to is what the next game is offered. The name is remembered once the write has come back rather than as it is typed, so a room that was never created and a join the room turned down leave nothing behind: what is worth offering back is a name somebody really played under. What comes back out is treated like anything else from outside the app — a stored value the nickname rules would refuse, one kept before the rules were what they are, is read as no name at all, so no field is ever filled with something the button then refuses to act on, and that filter lives in the store rather than in each of the two forms reading it. A browser with nowhere to keep a name, a private window or one with cookies switched off, is asked for a name on an unbroken screen exactly as before: reaching for storage there throws instead of answering empty, which is now survived in one place that the internal-traffic mark uses too. The name goes into that profile's own field and nowhere else, never into an analytics event and never into Sentry ([issue #75](https://github.com/vik8174/word-crossword-game/issues/75), [ADR 0023](docs/decisions/0023-a-screen-name-is-text-that-has-been-redacted.md))
- Three things a person needs and the tests cannot hold are written down. [`docs/releasing.md`](docs/releasing.md) is the order a version is published in, which until now existed only in the body of the ticket that cut 1.1.0 and would have been reconstructed from memory next time; the `Releasing` section of `CONTRIBUTING.md` now points at it rather than describing a second, shorter version of the same thing. [`docs/manual-checks.md`](docs/manual-checks.md) is the check by hand that was being reinvented, differently and incompletely, in every ticket that needed one — and that has found what the tests did not five times in this project. It is in two parts because it cannot all happen at once: what is looked at on stage before the tag, which stands on its own, and what only exists after a tag has deployed production, beginning with marking the browser profile as internal, since a visit made before that mark is counted forever. [`docs/known-limits.md`](docs/known-limits.md) gathers the seven limits that were scattered across six places, each pointing at the record that accepted it and naming what would lift it — or saying plainly that nothing is going to, and how, rather than naming a ticket that does not exist ([issue #81](https://github.com/vik8174/word-crossword-game/issues/81))
- The pre-tag checklist knows how a game ends early, and says what to ignore while reading a console. The **End the game** control shipped without a step to look at it by hand, so the one time it was checked the check was invented on the spot and would have been invented again, differently, at the next release — the very state [`docs/manual-checks.md`](docs/manual-checks.md) was written against. The step is a room of its own rather than another line at the end of the session, because ending early is as terminal as playing to the end: the room the session finishes in no longer has the control in it, and somebody following the list in order would have gone looking for a button that cannot be there. What it asks to be looked at is the part no test reaches — the other player's screen changing by itself, and the two screens read against each other rather than each on its own, each player still seeing the words they were explaining and neither seeing the other's, which is what a room ended early being read as a finished one would give away by spelling the whole crossword out on both. The console step now also names what is expected to be in there and is not this app's: two warnings that gtag has overwritten the `expires` of its own session cookie, which every load produces on any site with GA4 on it, and a red `TypeError` from a browser extension's `h1-check.js`. Both were taken for leftovers of the cookie-domain fix the first time that step was walked after it landed, which is time spent proving that nothing is wrong ([issue #96](https://github.com/vik8174/word-crossword-game/issues/96))

### Fixed

- The console is no longer red on every load. Both addresses this app is served from end in `web.app`, which is in the Public Suffix List, and gtag's default `cookie_domain: auto` has only one way to find that out: it tries. Working from the broadest domain inwards, it asks the browser for a cookie on `web.app`, the browser refuses and writes a line about it, and eight such lines had been landing in the console on every single load. Nothing was actually broken by it — the narrowest attempt is accepted, so the cookies were written and the client id kept — but a permanently red console is one where the next real error reads as more of the same. Analytics is now told the host the page came from instead of being left to search for it, and that is the very domain the search was arriving at, so the same two cookies carry the same client id with none of the noise. The value is not hard-coded anywhere: production, stage and a local dev server each name their own host, read as Analytics starts. The pre-tag checklist gains the step that looks for all this, and loses two claims about stage that turned out not to hold — the request carrying the word count is not the first `collect` of a room, and whether stage's analytics property filters internal traffic the way production's does has never been checked ([issue #83](https://github.com/vik8174/word-crossword-game/issues/83)).
- The changelog entry for 1.1.0 is dated the day it was released, 2026-08-21, rather than the day its preparation started. The release commit and the tag are both from the 21st; the session that wrote the section down began on the 20th and ran past midnight ([issue #81](https://github.com/vik8174/word-crossword-game/issues/81))
- The workflows no longer depend on Node 20. Every run of CI and every deploy was writing `The following actions target Node.js 20 but are being forced to run on Node.js 24` — a substitution GitHub makes today and has announced it will stop making, at which point those steps stop starting and what breaks is not a test but the deploy, which is the worst moment there is. Four actions were pinned at `@v4` and all four target Node 20, not the three the warning listed: `actions/setup-java` runs only in the jobs that start the Firestore emulator, so it was named in one job's warning and absent from the other's. They are now `actions/checkout@v7.0.1`, `actions/setup-node@v7.0.0`, `pnpm/action-setup@v6.0.10` and `actions/setup-java@v5.7.0`, each of which declares `node24` in its own `action.yml` at that tag. The versions are exact rather than floating major tags, for the same reason `save-exact` is the rule for npm here: `@v4` is a tag its owner moves, and a move nobody asked for under a workflow nobody edited is exactly how this arrived. Nothing else in either workflow moved — not the Node the project is built with, which is 22 and a different decision, not the JDK the emulator runs on, and not the order of the steps, `pnpm/action-setup` still coming before `actions/setup-node` because `cache: pnpm` can only find a store when `pnpm` is already on the PATH ([issue #84](https://github.com/vik8174/word-crossword-game/issues/84))

### Changed

- `firestore.rules` refuse to turn one ending of a game into the other. Terminality used to be spelled as the single status a finished game carried, which was enough while there was only one way for a game to end; with two of them, the rules ask whether the room has ended at all and refuse every status but the one it ended with. It is not tidiness: the whole reason several clients may write the same ending in the same second without conflict is that the value does not depend on who wrote it, and a second possible ending breaks that exactly once — press End in the very second the last answer lands, and one client sees a full board while another has already decided. Refusing the move settles it without electing anybody, the first ending being what happened in the room and the second client being told no. Nothing else in the rules moved: the freeze on a started game's players, the check that only the host deals the words out, the protection of the host's own seat and the refusal to delete a room are all untouched ([issue #73](https://github.com/vik8174/word-crossword-game/issues/73), [ADR 0012](docs/decisions/0012-ending-a-game-from-the-received-state.md))
- The line under the crossword is a count and nothing more: `N words are hidden in this grid.` Three further sentences had been explaining the board over every screen of every room — that the words a player explains are written in for them in italics on dashed squares, that their own go into the highlighted ones, that a word's letters turn plain once it has been answered — and all three are learnt in the first minute of a game that has a live person on the other end of it. Nothing is lost by dropping them: the panel of words beside the grid already says the same two things, and says them better, each half of it standing over the very words it is about rather than over a board where both kinds of square are mixed together. What stays is the one fact the board cannot show — a word that did not fit is drawn nowhere, so how many are hidden in the grid is not the length of the list somebody typed in, and that difference is now held by a test rather than by the wording. The captions of a finished room and of one closed early are untouched: they are about other states and say other things ([issue #76](https://github.com/vik8174/word-crossword-game/issues/76))
- The board is the best of ten draws rather than the first one. The layout library places words at random, so the same list gives a different grid, and a different number of words left outside it, every time it is asked: ten near-disjoint three-letter words came back with three words outside the grid on a lucky call and six on an unlucky one, and which of those a room got was decided by nothing at all. Ten layouts are now built and the one with the fewest leftovers is kept, so that same list comes back with three every time. Equally good draws are settled in favour of the earlier one, and a draw that places every word ends the search there and then — which is what an ordinary list does on its first attempt, twenty everyday words placing all twenty in a hundred runs out of a hundred, so the ordinary room still pays one layout and 20 milliseconds. A draw is judged by the crossword this module built from it and never by the count the library reported: words are lost after the library returns as well, by an entry that carries no coordinates and by a placement whose letters contradict a letter already written, and the library's own number cannot see either of those. None of this promises that every word will be placed — words sharing no letters cannot cross, at any number of attempts, and the notice about words left out of the grid is as necessary as it ever was. Attempts also stop once half a second has been spent on them, because the price of a layout is not flat: the first word that cannot be placed switches the library's backtracking on, over a grid three times the longest word, and one layout of nineteen ordinary words plus an uncrossable `zzz` costs 320 milliseconds where twenty ordinary words cost 20. Ten of those in a row is half a minute of a frozen browser, spent inside the owner's click on "Create room" and buying nothing, the leftovers being identical on the tenth attempt and the first. The budget is checked before an attempt is started and never during one, so a list too expensive to lay out twice costs exactly one layout — what it cost before there was a second attempt ([issue #74](https://github.com/vik8174/word-crossword-game/issues/74), [ADR 0008](docs/decisions/0008-crossword-layout-library-and-contract.md))

## [1.1.0] - 2026-08-21

### Added

- My own visits can stop counting as players. Every check of the live app is made from a fresh isolated browser profile, and each of those is a new anonymous sign-in and, to GA4, a new person — thirty days of production counted nine "users" who were almost all the same one, which is enough noise to lose the first real players in. Opening any page with `?internal=1` now marks that browser profile, `?internal=0` unmarks it, and every event from a marked profile carries `traffic_type=internal` for the GA4 Internal Traffic filter to exclude. The mark is remembered in the profile's own storage rather than matched on an IP address, because a home address is dynamic, is shared with the neighbours behind CGNAT, and cannot be proven to be mine — a rule built on one stops matching quietly on the day it changes, while a mark the browser carries survives a changed address, CGNAT and a VPN alike. It rides in the very object that names the page, since `setDefaultEventParameters` replaces the whole set of defaults instead of adding to it and would otherwise have wiped it on the first navigation. The parameter is taken back out of the address bar once read, and the invite link never carried it in the first place, so no real player is ever marked as me. A browser with nowhere to keep the mark — a private window, cookies switched off — is left unmarked and otherwise untouched, telemetry here never being allowed to fail loudly ([issue #68](https://github.com/vik8174/word-crossword-game/issues/68))
- Where people stop is measured. The four screens between opening the app and the first word being explained — the home page, `/create`, the nickname form and the lobby — each report that they were reached, so the drop-off between them is read rather than guessed at. Two of them were already distinguishable by their address; the other two are the point, being two screens at one address that no page view could ever have told apart. An arrival is recognised by the name of the screen and by nothing else: a room screen is rebuilt on every snapshot and a live room receives one every fifteen seconds from each client marking itself present, so anything watching the screen itself would have reported four arrivals a minute at a screen nobody arrived at ([issue #51](https://github.com/vik8174/word-crossword-game/issues/51), [ADR 0023](docs/decisions/0023-a-screen-name-is-text-that-has-been-redacted.md))
- Analytics events may now carry text, on the one condition that it has been through the redaction. `Redacted` is produced in a single place and nowhere else, so a room id, a nickname, a word or the address bar still cannot be handed to an event as it stands — what replaced "numbers, and nothing else" is "what has not been redacted does not compile", checked by the compiler exactly where the old rule was. The event that carries a screen name narrows it further and takes four fixed words rather than text, so there is nothing a player typed for it to be given ([issue #51](https://github.com/vik8174/word-crossword-game/issues/51), [ADR 0023](docs/decisions/0023-a-screen-name-is-text-that-has-been-redacted.md))
- Players are shown who is still there. Every client rewrites a mark of its own in the room every 15 seconds, and a player whose mark is more than 45 seconds old is named as away beside their name, with how long it has been — the difference between somebody thinking and somebody gone, which is what decides whether the other one keeps waiting or keeps explaining into nothing. Only that deviation is labelled: a line every row carries says nothing, which is what `Players (2 of 4)` cost. A room that is over shows none of it, since nobody marks themselves present in a finished game ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47), [ADR 0022](docs/decisions/0022-a-mark-a-player-writes-for-themselves.md))
- A player the room has stopped hearing from is told so, on their own screen. Firestore serves a client its own writes from cache, so somebody whose connection has gone still sees their letters land in the grid and the room exactly as they left it, while the other player talks to nobody. Their own mark in the document they are reading goes stale at precisely the moment their writes stop arriving, because it is one of those writes — the same question, asked about the reader, with nothing taken from `navigator.onLine`, which reports a network rather than a database ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47), [ADR 0022](docs/decisions/0022-a-mark-a-player-writes-for-themselves.md))

### Fixed

- A guest the room turns away is told about the room rather than about their connection. Joining writes `players.<uid>` without re-reading the room by decision, so the security rules are the only thing standing between two guests reaching for the same free seat — and since a lobby seat frees itself once its mark is 60 seconds old, two people opening the link within the same minute read the same free seat as a matter of course. Whoever was a moment slower was shown _Check your connection and try again_, a network fault reported to somebody whose network was fine. A refusal and an unreachable database are now told apart in one place, by the code Firestore attaches to the failure, and the guest who lost is offered a room of their own instead of a button that would be refused all over again. No cause is named, because none is given: a refused write is answered with `permission-denied` and nothing more, so a room that filled up, a game dealt out while a nickname was being typed and a room past its 24 hours all arrive as the same fact. What is shown says only that much, and gives way to the room's own words the moment the next snapshot lands — the subscription behind the nickname form never stopped running. A join that genuinely could not reach the database still says so, word for word as before ([issue #50](https://github.com/vik8174/word-crossword-game/issues/50), [PRD #31](https://github.com/vik8174/word-crossword-game/issues/31))
- One stray tab no longer costs the whole game. Opening the invite link on a second device signs that browser in as a player of its own, so a host checking their own link filled the room and the friend it was sent to met a wall — with no way out, since nothing removed a player, a room cannot be deleted and its 24 hours were the only exit. A visitor now takes a lobby seat whose mark is more than 60 seconds old, in the one write that also puts them in, so the room is never a size the security rules refuse. Never the host's seat: they are the likeliest to step out, being the one sending the link, and they alone can start the game ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47), [ADR 0022](docs/decisions/0022-a-mark-a-player-writes-for-themselves.md))
- `firestore.rules` hold a room's players frozen from the deal onwards: a player key can no longer disappear once a room is `playing` or `completed`. The check asked only that the keys after a write be among the keys before it, which refuses an arrival and permits a departure — and a player dropped from a game leaves their words hidden from nobody, so the crossword can never be finished and there is no way back, `completed` being terminal and the room undeletable. The lobby stays open, which is where a seat that was given up can change hands ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47), [ADR 0022](docs/decisions/0022-a-mark-a-player-writes-for-themselves.md))
- `firestore.rules` refuse to let the host be taken out of the room they made, in any state. A lobby's roster is otherwise every client's to write — which is what lets an arriving player take a seat nobody is sitting in — so without this the one seat presence never frees could still have been taken by anybody holding the link ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47), [ADR 0022](docs/decisions/0022-a-mark-a-player-writes-for-themselves.md))
- Setting up a deploy no longer costs a failed deploy to find out what the runbook left out. The service account needs a fourth role — Service Usage Consumer — because publishing `firestore.rules` makes the CLI ask whether the Firestore API is enabled, which the three roles listed before did not allow; the failure named neither the role nor the step, arriving as `403 Permission denied to get service [firestore.googleapis.com]` after everything else had succeeded. The deploy also checks the service account key before it builds: that it is JSON, that it is a service account key rather than a field of one or a path to the file, and that it belongs to the project being deployed to — so a key pasted wrongly, or a production key left in the stage environment, is named as such instead of surfacing at the last command as `Failed to authenticate, have you run firebase login?` ([issue #53](https://github.com/vik8174/word-crossword-game/issues/53))
- Reloading after creating a room no longer loses the room. The room id and the words that built it were held in component state on `/create`, so a reload, a closed tab or a crash destroyed the owner's only way into the game they had just made — the one player who could not get the link back out of an address bar. The owner is now inside the room at its own address, and every screen there is derived from the room document, so coming back to the link is safe at every point of a game ([issue #48](https://github.com/vik8174/word-crossword-game/issues/48), [ADR 0021](docs/decisions/0021-one-room-address.md))

### Changed

- A word may now be up to 16 letters, where 12 was the ceiling. Twelve cut out ordinary vocabulary that is exactly what the game is played to practise — `responsibilities`, `misunderstanding`, `characterization` — and a long word is the hardest one to put in other words, which is what makes it worth being dealt. The number lives in `MAX_WORD_LENGTH` and nowhere else: the validator's message and the line under the word-list field both read it, so no copy in the app states a length of its own any more. The grid pays for this in width, and the width is recorded rather than treated. Twenty words at the old ceiling already drew 25 columns and 850 pixels, not the 22 and 746 [ADR 0017](docs/decisions/0017-desktop-first-while-the-grid-outgrows-a-phone.md) had estimated, and twenty words of 13 to 16 letters draw 43 columns and 1462 pixels — wider than the 1280 of a typical desktop window, which is the platform 0017 named as its target. A realistic mixed list, ten long words and ten ordinary ones, is 29 columns and 986 pixels and still fits. How the board is drawn is 0017's open question and is untouched here, so a grid wide enough to overflow the room's container is played with a horizontal scroll on a desktop as well as on a phone, as it already was before this change ([issue #69](https://github.com/vik8174/word-crossword-game/issues/69), [ADR 0017](docs/decisions/0017-desktop-first-while-the-grid-outgrows-a-phone.md))
- The invite link is the host's, and it is on the screen only while the room still has a seat. A guest used to arrive by that link and then be shown it again above their own lobby, with a copy button — an invitation to pass on a URL that would send whoever received it straight to a refusal, since a room is played by exactly two and it was full the moment they walked in. It is now shown to the host alone, and it goes when their guest arrives. "Has a seat" is not a count of the players: a lobby seat frees itself once its mark is 60 seconds old, so a host whose guest closed the tab gets the link back within a snapshot and can fill the room again, and the same expression answers that question for the visitor at the door and for the panel, rather than two conditions drifting apart. The price is named rather than hidden: who the reader is cannot be known without the room document, so the panel now waits for the first snapshot instead of standing on the screen while the room is still being read — the host sees their link a moment later, and the guest never sees it at all. The panel itself is untouched, link and copy control and all, and it stays where it was above whatever the room is showing ([issue #70](https://github.com/vik8174/word-crossword-game/issues/70), [ADR 0026](docs/decisions/0026-the-invite-link-belongs-to-the-host.md))
- What happens to the seat of a player who left is now written down, in all four cases there are, and one of the numbers behind it is smaller. The behaviour was already right and does not change: in a lobby the host's seat is kept for as long as the room exists while a guest's is given to whoever arrives next, and once the words are dealt both are frozen — a player who disappears mid-word can always come back to their own game, and nobody else can be let into it. Answering any of that meant reading three modules and two comments in the security rules, so it is stated as a decision and asserted as four tests named after the four cases, with the two the rules hold checked against the emulator rather than only agreed to by the client. A lobby seat is now freed after 60 seconds of silence instead of 90: holding it protects a guest who stepped out, and it equally leaves a host whose guest is simply gone with a full room and nobody to give the seat to. The gap to the 45 seconds that merely marks somebody away is kept, because a line beside a name is taken back the moment its player writes again and a seat given away cannot be. Two limits are named rather than left to be discovered — a host who lost their browser identity cannot be recognised as the host, and a guest who never returns after the deal leaves a game with no way to end it — along with the fact that a room's 24 hours are counted from its last write and not from the moment somebody left, so a room nobody can finish stays alive for as long as a tab is open on it ([issue #71](https://github.com/vik8174/word-crossword-game/issues/71), [ADR 0025](docs/decisions/0025-what-happens-to-the-seat-of-a-player-who-left.md))
- A game is played by two, and that is now recorded as a decision rather than left as a limit somebody would raise later. [Issue #10](https://github.com/vik8174/word-crossword-game/issues/10) is closed as not planned, for a reason no implementation would move: every word is hidden from one of the two players the deal was made to, so a third person would have the whole crossword to read and nothing to guess — an audience rather than a player. The constant behind the lobby's sentence is now named for what it is, `PLAYERS_PER_GAME` instead of `MAX_PLAYERS`, since a maximum implies a range beneath it and there is none. The one comment that named #10 as the change which would reword it names the record instead, and the ceiling language in the three comments around it goes with it. What did not change is `assignWords`, which still deals to any number of players from two upwards, its tests on rooms of three and four included. That generality is not a spare part for a cancelled feature — it is the shape of the rule the game runs on, that a word is hidden from exactly one player and the rest explain it, which is a sentence about one and the rest rather than about two. `packages/shared` knows the rule and `apps/web` knows the size, so the two constants that both read `2` stay two constants ([issue #66](https://github.com/vik8174/word-crossword-game/issues/66), [ADR 0024](docs/decisions/0024-two-players-are-the-product-not-the-algorithm.md))
- A room is for two players, and the client, the security rules and every sentence the game shows now say it the same way. The ceiling was four in `MAX_PLAYERS` and in `firestore.rules`, while the game has only ever been played by two — the words are dealt from two players up — so a third guest with the link was told the room was full rather than that a game here is a pair. Both numbers moved in one change because they had to: joining writes `players.<uid>` without re-reading the room, so the rules are the only gate, and a client stopping at two while the rules still took four would have opened a two-seat race on the way in where none existed. The third guest is now told what the game is and offered a room of their own, and the lobby states the size a game is played at instead of naming a ceiling to work towards. Nothing supporting larger rooms was removed — `assignWords` still has no upper bound at all ([issue #49](https://github.com/vik8174/word-crossword-game/issues/49), [PRD #31](https://github.com/vik8174/word-crossword-game/issues/31))
- Creating a room takes the owner into it. A room has one address, `/room/<id>`, and creation replaces `/create` with it in history rather than pushing, so Back leads out of the flow instead of to a filled-in word list — going back to one invites creating a second room the guests were never sent to. The invite link travels with the owner: it is on the room screen now, above whatever the room is showing, so every player can pass it on, and it is there while the room is still being read because the link is built from the address and waits for no snapshot. It goes once the words are dealt out, when sharing it would only send a friend to a refusal ([issue #48](https://github.com/vik8174/word-crossword-game/issues/48), [ADR 0021](docs/decisions/0021-one-room-address.md))

### Known limitations

Shipped knowingly, ticketed where there is a ticket, and named here rather than left for whoever plays the game to find. All three of 1.0.0's are closed:

- **The crossword is wider than the box it is drawn in, and scrolls sideways.** It always was on a phone; on a desktop the board sits in a container of about 552 pixels, so twenty ordinary words already overflowed it before this release. Sixteen-letter words make the widest boards wider still, far enough that the worst case outgrows a 1280-pixel window as well. The board is navigable either way — tapping a word in the panel beside it takes the player there — and how it might be drawn instead is an open question rather than an oversight ([ADR 0017](docs/decisions/0017-desktop-first-while-the-grid-outgrows-a-phone.md))
- **A host who loses their browser identity cannot be recognised as the host again.** A player is a UID issued per browser profile, so clearing site data, switching profile or reopening the link in a private window comes back as somebody else. The host's seat is the one seat nothing ever frees, so it is held for a UID no browser can produce any more: the room can never be started and lives out its 24 hours waiting. Until there is real sign-in, which the MVP rules out, the browser that made a room is the browser that plays in it ([ADR 0025](docs/decisions/0025-what-happens-to-the-seat-of-a-player-who-left.md))
- **A guest who never comes back after the words are dealt leaves a game that cannot end.** Every seat is frozen from the deal onwards, so nobody replaces them, and a room is only ever `completed` when every word has been answered — which the words hidden from the missing player cannot be. The one who stayed has no way to close the room or to leave it; it waits out its lifetime, and that lifetime is counted from the last write to it rather than from the moment anybody left, so it stays alive for as long as a tab is open on it. A leave control and an early end to a game are [issue #73](https://github.com/vik8174/word-crossword-game/issues/73) ([ADR 0025](docs/decisions/0025-what-happens-to-the-seat-of-a-player-who-left.md))
- **My own visits keep counting as players until each browser profile is told not to.** The internal-traffic mark belongs to one profile, and a fresh isolated one knows nothing of it, so a check made from a new profile without opening `?internal=1` first is recorded as another person. Nothing about it is retroactive in either direction ([issue #68](https://github.com/vik8174/word-crossword-game/issues/68))

### Changed

- The desktop is the target while the grid does not fit a phone. A square is 32 pixels with a 2-pixel gap, so a crossword of 17 columns is 576 pixels across and one of 22 is 746, against a phone's 375 — between a third and a half of the board is off screen. Reaching a word from the panel made that navigable and did not make it fit. Recorded as a stated limitation rather than left as an unspoken intention, and deliberately not answered yet: whether the phone is served by drawing the board differently or by a room that cannot produce a board this wide belongs to [issue #31](https://github.com/vik8174/word-crossword-game/issues/31) ([ADR 0017](docs/decisions/0017-desktop-first-while-the-grid-outgrows-a-phone.md))
- The words a player has to explain are written into their own grid, in place, instead of sitting in a list beside a board with nothing in it. An explainer can now see how long their word is, where it sits and everything it crosses, and may say so out loud — which is what makes the thing on screen a crossword rather than a diagram. A square says why its letter is there: answered by the group, or this player's own to explain, told apart by a dashed outline and a slanted letter as well as by a tint, and a word visibly turns plain for its explainer the moment its guesser answers it. Telling those two apart is what keeps somebody explaining a word nobody has guessed yet. The invariant three tickets were built on is inverted rather than dropped, and is asserted the way it is now stated: no word hidden from a viewer appears anywhere in their rendered document — checked over the whole document, against every word the room hides from them ([issue #41](https://github.com/vik8174/word-crossword-game/issues/41), [PRD #32](https://github.com/vik8174/word-crossword-game/issues/32), [ADR 0015](docs/decisions/0015-explained-words-in-the-grid.md))
- Between 17.3% and 26.0% of a player's own letters — at two and at four players — now arrive already written, because a word they explain crosses one they must guess, and the most-covered single word in thirty measured grids arrived 67% written. Accepted as measured rather than mitigated: no word was ever covered completely, and a word that arrives free costs one word of play rather than the game. [ADR 0015](docs/decisions/0015-explained-words-in-the-grid.md) carries the numbers and says why each mitigation was rejected ([issue #41](https://github.com/vik8174/word-crossword-game/issues/41))
- The panel beside the grid is an index rather than a word list: two numbered lists, the words this player explains and the words they guess, each named the way the players say them out loud — "one down", "three across". The second replaces the counter that was there, so a guesser can ask for one of their own words to be explained again by name. Of the words hidden from them it still holds no letter and no length ([issue #41](https://github.com/vik8174/word-crossword-game/issues/41))
- A letter written into the grid because this player explains the word through it counts towards a word of theirs crossing it, exactly as an answered letter already did — the letter is right and in front of them, and retyping it would be copying what they can read. A room closed before its crossword was finished now says that the words nobody guessed are not spelled out _apart from the ones that were yours to explain_, which were on that reader's screen all along ([issue #41](https://github.com/vik8174/word-crossword-game/issues/41), [ADR 0011](docs/decisions/0011-typing-guesses-into-the-grid.md))
- All repository documentation and code comments are written in English
- The room screen is chosen as a value rather than assembled from flags. `roomScreenFor` composes what the connection, the access rules and the board already know and answers with one of seven screens — connecting, unavailable with a reason, join, lobby, playing, finished, closed early — which `RoomPage` renders through an exhaustive `switch`, so a phase added later cannot be handled in six places and forgotten in the seventh. Each phase is now its own component holding only what that phase can act on: the lobby owns the deal and what to say when it is refused, the game owns answers and the ending it watches for, and the two terminal screens take no callbacks at all, because they have nothing left to call. Nothing a player sees or can do changed; the previous single component decided between four phases through three booleans derived from one status field, of which eight combinations were expressible and four were real ([issue #38](https://github.com/vik8174/word-crossword-game/issues/38), [ADR 0009](docs/decisions/0009-room-document-schema.md))
- A finished game is now closed only by a client that is actually playing it. The watcher that writes `status: 'completed'` used to run above the access checks, so a stranger holding the link ran it too; it now lives on the playing screen, which only a player of a live game is shown. The one case this drops is a room whose players have all closed their tabs while an onlooker keeps the link open: that room stays in `playing` until the TTL policy collects it, which it already would have done for a room nobody has open at all ([issue #38](https://github.com/vik8174/word-crossword-game/issues/38), [ADR 0012](docs/decisions/0012-ending-a-game-from-the-received-state.md))
- Letters typed into the grid but never accepted no longer survive a room being closed with words still unanswered. They were drawn on under a notice saying the room was closed and beside a caption promising that unanswered words stay blank; a game played to its end is unaffected, because every square of a full crossword already holds its solved letter ([issue #38](https://github.com/vik8174/word-crossword-game/issues/38))

### Fixed

Nothing takes them in on its own: the invitation is usually sent before its owner walks in, so the choice stays theirs ([issue #27](https://github.com/vik8174/word-crossword-game/issues/27))
- The lobby no longer implies a game needs four players. A game starts from two, and the room said the opposite in three places at once: one status line about waiting shown to everybody — the owner included, directly above a **Start the game** button they could press right then — a `Players (2 of 4)` counter that read as progress towards four, and nothing at all telling everybody else that the owner is the one who starts. The two roles are now told different things: the owner hears whether they can start and what is missing if they cannot, everybody else hears that the game is the host's to start and so has a reason to wait. Both lines follow `wordAssignmentRefusal` — the same question the start button asks and `assignWords` asks itself — so the screen cannot come to disagree with the button again. The counter is now `Players (2)` with the room's capacity said as a ceiling beside it, and who may start a game, and from how many players, is unchanged ([issue #29](https://github.com/vik8174/word-crossword-game/issues/29))
- A room's 24 hours now restart with every write to it, instead of being fixed once at creation. `expiresAt` looked like housekeeping for the Firestore TTL policy, but the security rules read it on every update, so a room whose expiry stopped moving stopped accepting writes the moment it ran out: a game played across more than a day died in the middle of itself, refusing answers and unable to be finished. Every update a game makes — a player joining, the words being dealt out, a word being answered, the game being closed — is now built in one place and carries a fresh expiry, and the type of a room update is one only that place can produce, so a write added later cannot quietly skip it ([issue #9](https://github.com/vik8174/word-crossword-game/issues/9), [ADR 0013](docs/decisions/0013-keeping-a-room-alive-on-every-write.md))

### Known limitations

Shipped knowingly, ticketed, and named here rather than left for whoever plays the game to find:

- **Reloading the create screen loses the room and the words that built it.** The room id lives in component state and nowhere else, so a refresh between creating a room and sending its link leaves no way back into it — the words are typed again ([issue #48](https://github.com/vik8174/word-crossword-game/issues/48))
- **The product says it takes up to four players; in practice it takes two.** The word assignment deals from two players up, and the four in `README.md`, `CLAUDE.md` and the notice a turned-away guest reads is the size the game was planned at, not the one it has been played at ([issue #49](https://github.com/vik8174/word-crossword-game/issues/49))
- **The host's second device joins their own room as another player, with no way to undo it.** Opening the invite link in a second browser signs in as a new anonymous player, which fills a seat in the room the host already owns and cannot be given back ([issue #47](https://github.com/vik8174/word-crossword-game/issues/47))
