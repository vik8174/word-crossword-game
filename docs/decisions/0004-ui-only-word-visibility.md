# 0004. Приховування слів — лише на рівні UI, без Security Rules

Status: Accepted

## Context

Кожне слово в грі невидиме для одного гравця (того, хто його вгадує) і видиме решті. При архітектурі "клієнт напряму читає Firestore" ([0002](0002-no-dedicated-backend.md)) технічно можливо приховати дані двома способами: (а) не показувати приховане слово в UI, хоча воно фізично присутнє в отриманому документі; (б) розділити дані на під-документи з Firestore Security Rules, що забороняють конкретному гравцю читати конкретне поле/документ.

## Decision

Для MVP обрано варіант (а) — приховування тільки на рівні UI. Гравець технічно може прочитати "приховане" від нього слово через DevTools/Network, якщо навмисно захоче.

## Consequences

- Проста структура даних — весь стан кімнати в одному документі, без розбиття на під-колекції за правами доступу
- Чит технічно можливий, але це гра для знайомих людей на добровільній довірі, не змагання зі ставками — ризик визнано прийнятним для MVP
- Якщо в майбутньому зʼявиться публічний матчмейкінг із незнайомцями чи будь-який змагальний режим зі ставками — це рішення потрібно переглянути на користь варіанту (б)
